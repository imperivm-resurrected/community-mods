Row 1, issue #21. `community_mod_v12.rar` (GameBanana 730058, the author's own upload of 2026-10-20, 94 MB, `originals/gamebanana/730058/`): the mod's folder `Community Mod/` with `DATA`, `UNITS`, `BUILDINGS`, `UI`, `RANDOMMAP`, `Local/<language>` (text and voices), maps, a conquest and the author's `mod.json`. It is made for HD (no 1.40 merge: its classes and scripts are HD's plus the mod's edits). `authors`: Ferónidas and `Villoh (port)`.

- **Permission**: the authors' permission was granted to the maintainer, per the maintainer, 2026-11-01. That is the maintainer's statement; there is no document to quote.

## Rebuild

```bash
node tools/community-mod.js [id ...]     # no id: all eight; SDK=<imperivm-resurrected/sdk> overrides the SDK it finds
```

It unpacks the rar into `.scratch/cm-src` (inside the worktree, git-ignored; nothing is written under `originals/`), copies the mod's folder into `.scratch/cm-pristine` without what is not the civilizations' (below), rebuilds `ported/community-mod-civs` from that and does the rest. The SDK is the repository next to the main checkout (`SDK` overrides it; `clone-civs.js` runs its `clone-civilization.js`). **The other ports** the names are compared with (`tagCollisions`, the orders and items clash check) are read from the main checkout (the parent of `git rev-parse --git-common-dir`) **and** from the worktree's `ported/` (the worktree's wins), so a build from `.wt/` sees what only the main checkout has (Mediterranevm alpha, MCI, Imperivm Legacy; git-ignored). The build **stops** with a message if `imperivm-legacy`, `mci`, `mediterranevm-alpha`, `cgwar`, `greek-mod-1-8` or `greek-civilization-mod` is missing, unless `CM_NO_OTHERS=1` (the names tagged then differ). A placeholder at `UI/CMDBAR/ACTIONS/HOVER.BMP` makes the build tag that name too: the built Caesar Mod port (`.wt/caesar-mod-civs`, 2026-11-01) ships the same path with other bytes. `extras/community-mod-civs/mod.json` is copied over at the end; there are no other hand fixes: the fixes the build applies are in the tool, each with its reason. Same commit, same bytes from either place: 1736 files of the port plus the 9 `raw/community-mod-civs-*.txt`, `md5sum` of every file identical between the build in `.wt/community-mod-civs` and the build in a clean worktree at `/tmp` (list md5 `5dc25c016f867859dece474fd73488b3` both; a build from the main checkout itself was not made, it is on `main`). A first try differed in `community-mod-civs-maps.txt` (it read the maps relative to the worktree): fixed. The build stops if a script it writes is unbalanced, a patch of a game script does not apply, a class name a script writes as text does not exist, or a picture, sound entity, sound file or entity a text names is missing and the rar's own package resolved it. Libraries: `tools/lib/community-refs.js` and `tools/lib/community-names.js` (new, below; the second is a copy of the Greek chain's `greek-2x-names.js`, with the item scripts counted as reachable); `tools/lib/own-scripts.js`, `clone-civs.js`, `asvr-ai.js`, `asvr-inline.js`, `menu-skin.js`, `conquests.js`, `ported-patch.js` are used as they are (no change to any shared tool; nothing for `PR-NOTES.md`).

## What the mod changes (against HD) and where it went

The mod changes 160 of HD's classes and adds 35 (the 36 files of the rar, one of them unloadable, below); 32 command files; 138 scripts of `SUBAI` and 28 new; 9 AI scripts; 30 item scripts; 16 menu INIs; 14 new random-map templates and 41 changed bitmaps/templates; 120 unit and 6 building entities; 17 adventures, 6 scenarios and one conquest.

**A civilization's (the eight)**: the mod's version of every class of the civilization (stats, costs, specials, orders), cloned from HD by `clone-civilization.js --all-orders` (`tools/lib/clone-civs.js`). The mod's own classes come with it: the hero variants (`BHero4`, `4a..c`, `CHero5`, `GHero5a..7b`, `IHero5..`, `MHero1..4`, `RHero1..4`, `THero4`, `EHero4`) and the second spearmen/swordsmen of Britain and Gaul's trident warrior (`BBronzeSpearman2`, `BHighlander2`, `BShieldBearer2`, `BSwordsman2`, `GTridentWarrior2`), 34 in all, each renamed for the civilization (`FbrHero4`…). `RLiberatus` (the mod gives it race ImperialRome) is the Republican copy's with the Republican race, and Imperial Rome has its own. **What the mod changed in the base classes** (`Unit`, `Hero`, `Military`, `Ranged`, `Sentry`, `Outpost`, `Catapult`, `BaseShipyard`, `BaseTownhall`, `BaseMage`; 142 classes in `base-changes`) is written **inside each clone**, never in HD's class.

**Scripts the mod edited** (`tools/lib/own-scripts.js`, tag `cm`): copies `<name>_cm.vs` (and `<name>_cm_<id>.vs` where the class ids the script writes as text differ per civilization), which only the clones' classes and commands point to; the game's scripts are the game's. 8406 `<method>` of the game's classes whose script the mod edited are written inside 407 clone classes. The behaviors the clones inherit from the game's classes and the mod edited (`arena_behavior.vs`, `village_behavior_givefood.vs`) go as one block per civilization **inside a patch of the game's script** (`patches/DATA/SUBAI/`, `asvr-inline.js`): `if (Mod_TrueRace(This) == Fgaul) { … return; }`; the game's civilizations never enter a block. Read `imperivm-mod.log` for `compilation error` first: an error in one of these patches stops the script for every civilization. The ones left to the game's (the mod's edit is not ported because a copy cannot replace an inherited behavior): `stamina_counter.vs` (RamUnit), `gate_patrol.vs` (Gate), `settlement_behavior_ambient.vs` (BaseTownhall, BaseVillage), `townhall_autotrain.vs` (BaseTownhall), `wall_patrol.vs` (Wall), `summoning_behavior.vs` (SummoningUnit). `raw/community-mod-civs-own-scripts.txt` lists the copies. `.race == Gaul` tests in the copies also accept the clone (`|| Mod_TrueRace(X) == Fgaul`); the class ids a script writes as text are each clone's own (a check looks for unprefixed ones and stops the build: none left outside the game's own scripts).

**Items**: the 14 items the mod adds (`Slumbering stone`…), with their item scripts, as a patch of `ITEMS.XML` (`patches/DATA/ITEMS.XML`). The 25 items of the game it edits are not (below). Item ids can clash with the Caesar Mod port's (same lineage): not checked, Caesar's port was not built when this was; `shared-paths.js` does it.

**Orders**: each civilization's command file (`DATA/COMMANDS/F<CIV>.XML`, 41-60 orders), the shared orders patched to name the clones, and `COMMUNITYMOD.XML` for the two orders of the base classes (`Gate`, `Outpost`…) whose sources became the port's classes (10 more orders for base classes with no class of this port under them are left out).

**The AI** (`tools/lib/asvr-ai.js`, prefix `CM_`): the mod's AI folder changes little: the researches and charms the AI buys (the mod's *Hunting Festival* instead of *Gambling*, *Charm of Seth/Thoth/Ra/Isis*), the Britons' research order, three tactics (Gaul, British, Imperial Roman), the class the outpost counter looks for (`CMacemen`) and the pick of `GetTacticScript` (always the first tactic of each civilization, instead of one of two or three). 14 copies (`CM_ES_Stronghold`, `CM_ES_Village`, `CM_ESH_Market`, `CM_ESH_NeedTech`, `CM_ESH_ResearchTraining`, eight tactics, `CM_TS_AttackAtWill`) in `[EconomyScripts]`/`[TacticScripts]`/`[Scripts]`, picked by patches of `GetEconomyScript.vs` and `GetTacticScript.vs` only for the eight (the `Main.vs` patch the lib also writes is removed, review item 5) (`Mod_TrueRace` / `Mod_PlayerCiv`). **Engine #15** (a `Sleep` inside a script started with `AIRun` crashes the game): the economy loops are never started with `AIRun`; the three helpers the loops start (`CM_ESH_*`) have no `Sleep` (checked with `grep`: 0); the tactics `AIRun` `CM_TS_AttackAtWill` with its `Sleep`, as the game's own do. Two caveats: the lib hard-codes a 5-second window for the tactic pick (the mod's, like HD's, is 2 seconds); and *Hunting Festival* / the *Charm of Seth* family are orders of the mod: whether the engine's translation of a clone's AI maps those names to each clone's own copy was not checked in the engine (AGENTS.md says to look in the Ghidra export before claiming; not done). Not ported: `AIOSendSquad` (the engine calls it by name with no player; the mod changes a 10-minute wait to 1 minute).

**Art and sounds**: the 120 unit and 6 wall/gate entities with other bytes than HD's are renamed alone (`BHERO1.ENT_cm.XML` next to the game's sprites in the same folder: `tagCollisions` with `gameDirs`, the entity names its images relative to its folder) and the clones' classes name them; the 6 building entities are wall and gate sort offsets only. 6 `EMACE_ATTACK` sounds and four new fight sound entities (`UnitBigAxeFight`, `UnitEMaceFight`, `UnitHeavySwordFight`, `UnitSlingFight`: HD's classes do not name them, only the mod's do, so the game is not affected). 105 files of `RANDOMMAP` art and 111 of `UI` (command icons, research and upgrade pictures, infobar; names that collide with the game's are `_cm`).

## Review of #46 (2026-11-01): what was found and what the files support

1. **`UI/CMDBAR/UPGRADES/BSHIELDS.BMP`** has other bytes than Mediterranevm alpha's; from `.wt/` the build did not see that port. Now both files are `_cm` (`UI/CMDBAR/UPGRADES/BSHIELDS_cm.BMP`, `UI/ICONS/UPGRADES/BSHIELDS_cm.BMP`) and `FBRITAIN.XML` names `_cm` in the `queueicon` (line 346) and the `button` (line 348). Audit of **every** picture reference (`button`, `queueicon`, `icon`, `image`; `rollover` and `help` are texts, not pictures; 2622 references): 24 file names are named plain in one folder and `_cm` in another (`GHOST`, `STRONGHOLD DEFENSE`, `CSPEARS`, `STATUE OF ISIS`, `AXE IRON`…); in all 24 the plain one resolves to **the game's** file in the other folder (the mod ships only one of the two), and **0** references name a plain path for which the port ships the `_cm` twin. `community-refs.js` now stops the build on that last case (self-tested).
2. **Names that differ only by case**: `research_cm.vs`/`RESEARCH_cm.VS`, `catapult_attack_cm`, `catapult_autofire_cm` (the copy the clones name, from `own-scripts.js`, and the mod's own script renamed by `tagCollisions`: same bytes). The build keeps the lower-case-extension one and stops if two such files ever have other bytes.
3. **The outpost loyalty block of `unit_on_kill_cm_<id>.vs`** (`Victim.player == 15`): the review was right about the symptom, the cause was one step before it. `defender_cls_N` of the copies' outposts said the **game's** class (`"BShieldBearer"`): `clone-civs.js` leaves it, the engine spawns the class by name (`defender_cls_1` is a `std::string` of the class, `imperivm-iii-research/analysis/modules/P21.md`), so a copy's outpost raised the game's defender (HD stats) and the block, which names the copy's classes, could not see it.
