# Community Mod 12 (Ferónidas)

Row 1, issue #21. `community_mod_v12.rar` (GameBanana 730058, the author's own upload of 2026-10-20, 94 MB, `originals/gamebanana/730058/`): the mod's folder `Community Mod/` with `DATA`, `UNITS`, `BUILDINGS`, `UI`, `RANDOMMAP`, `Local/<language>` (text and voices), maps, a conquest and the author's `mod.json`. It is made for HD (no 1.40 merge: its classes and scripts are HD's plus the mod's edits). `authors`: Ferónidas and `Villoh (port)`.

- **Permission**: the authors' permission was granted to the maintainer, per the maintainer, 2026-11-01. That is the maintainer's statement; there is no document to quote.
- **Licence**: `CC-BY-NC-ND-4.0`, as the author's own `mod.json` in the rar documents it (our `extras/community-mod-civs/mod.json` repeats it, `redistributable: true`).
- Nothing here is uploaded. The original upload on GameBanana stays as it is; this is a port with its credit.

**This port is the mod's balance as eight civilizations of its own, next to the game's** (AGENTS.md, *Civilizations are independent*; decided in #15: copies + room set). The game's eight are not touched, and nothing here is an exclusive ruleset. The reserved token is `f` (assigned by the coordinator): every id starts with it.

The set is named after `mod.json` `name`: **Community Mod 12** (16 characters, #38; next to Caesar Mod it cannot be mistaken); the longest lobby name, `Rep. Rome (Community)`, is 21.

## Rebuild

```bash
SDK=<imperivm-resurrected/sdk> node tools/community-mod.js [id ...]     # no id: all eight
```

It unpacks the rar into `.scratch/cm-src` (inside the worktree, git-ignored; nothing is written under `originals/`), copies the mod's folder into `.scratch/cm-pristine` without what is not the civilizations' (below), rebuilds `ported/community-mod-civs` from that and does the rest. `SDK` is needed by `clone-civs.js` (it runs the SDK's `clone-civilization.js`). `extras/community-mod-civs/mod.json` is copied over at the end; there are no other hand fixes: the fixes the build applies are in the tool, each with its reason. Same build twice, same files: 1752 files, `md5sum` of every file identical (checked). The build stops if a script it writes is unbalanced, a patch of a game script does not apply, a class name a script writes as text does not exist, or a picture, sound entity, sound file or entity a text names is missing and the rar's own package resolved it. Libraries: `tools/lib/community-refs.js` (new, below); `tools/lib/own-scripts.js`, `clone-civs.js`, `asvr-ai.js`, `asvr-inline.js`, `menu-skin.js`, `conquests.js`, `ported-patch.js` are used as they are (no change to any shared tool; nothing for `PR-NOTES.md`).

## What the mod changes (against HD) and where it went

The mod changes 160 of HD's classes and adds 35 (the 36 files of the rar, one of them unloadable, below); 32 command files; 138 scripts of `SUBAI` and 28 new; 9 AI scripts; 30 item scripts; 16 menu INIs; 14 new random-map templates and 41 changed bitmaps/templates; 120 unit and 6 building entities; 17 adventures, 6 scenarios and one conquest.

**A civilization's (the eight)**: the mod's version of every class of the civilization (stats, costs, specials, orders), cloned from HD by `clone-civilization.js --all-orders` (`tools/lib/clone-civs.js`). The mod's own classes come with it: the hero variants (`BHero4`, `4a..c`, `CHero5`, `GHero5a..7b`, `IHero5..`, `MHero1..4`, `RHero1..4`, `THero4`, `EHero4`) and the second spearmen/swordsmen of Britain and Gaul's trident warrior (`BBronzeSpearman2`, `BHighlander2`, `BShieldBearer2`, `BSwordsman2`, `GTridentWarrior2`), 34 in all, each renamed for the civilization (`FbrHero4`…). `RLiberatus` (the mod gives it race ImperialRome) is the Republican copy's with the Republican race, and Imperial Rome has its own. **What the mod changed in the base classes** (`Unit`, `Hero`, `Military`, `Ranged`, `Sentry`, `Outpost`, `Catapult`, `BaseShipyard`, `BaseTownhall`, `BaseMage`; 142 classes in `base-changes`) is written **inside each clone**, never in HD's class.

**Scripts the mod edited** (`tools/lib/own-scripts.js`, tag `cm`): copies `<name>_cm.vs` (and `<name>_cm_<id>.vs` where the class ids the script writes as text differ per civilization), which only the clones' classes and commands point to; the game's scripts are the game's. 8406 `<method>` of the game's classes whose script the mod edited are written inside 407 clone classes. The behaviors the clones inherit from the game's classes and the mod edited (`arena_behavior.vs`, `village_behavior_givefood.vs`) go as one block per civilization **inside a patch of the game's script** (`patches/DATA/SUBAI/`, `asvr-inline.js`): `if (Mod_TrueRace(This) == Fgaul) { … return; }`; the game's civilizations never enter a block. Read `imperivm-mod.log` for `compilation error` first: an error in one of these patches stops the script for every civilization. The ones left to the game's (the mod's edit is not ported because a copy cannot replace an inherited behavior): `stamina_counter.vs` (RamUnit), `gate_patrol.vs` (Gate), `settlement_behavior_ambient.vs` (BaseTownhall, BaseVillage), `townhall_autotrain.vs` (BaseTownhall), `wall_patrol.vs` (Wall), `summoning_behavior.vs` (SummoningUnit). `raw/community-mod-civs-own-scripts.txt` lists the copies. `.race == Gaul` tests in the copies also accept the clone (`|| Mod_TrueRace(X) == Fgaul`); the class ids a script writes as text are each clone's own (a check looks for unprefixed ones and stops the build: none left outside the game's own scripts).

**Items**: the 14 items the mod adds (`Slumbering stone`…), with their item scripts, as a patch of `ITEMS.XML` (`patches/DATA/ITEMS.XML`). The 25 items of the game it edits are not (below). Item ids can clash with the Caesar Mod port's (same lineage): not checked, Caesar's port was not built when this was; `shared-paths.js` does it.

**Orders**: each civilization's command file (`DATA/COMMANDS/F<CIV>.XML`, 41-60 orders), the shared orders patched to name the clones, and `COMMUNITYMOD.XML` for the two orders of the base classes (`Gate`, `Outpost`…) whose sources became the port's classes (10 more orders for base classes with no class of this port under them are left out).

**The AI** (`tools/lib/asvr-ai.js`, prefix `CM_`): the mod's AI folder changes little: the researches and charms the AI buys (the mod's *Hunting Festival* instead of *Gambling*, *Charm of Seth/Thoth/Ra/Isis*), the Britons' research order, three tactics (Gaul, British, Imperial Roman), the class the outpost counter looks for (`CMacemen`) and the pick of `GetTacticScript` (always the first tactic of each civilization, instead of one of two or three). 14 copies (`CM_ES_Stronghold`, `CM_ES_Village`, `CM_ESH_Market`, `CM_ESH_NeedTech`, `CM_ESH_ResearchTraining`, eight tactics, `CM_TS_AttackAtWill`) in `[EconomyScripts]`/`[TacticScripts]`/`[Scripts]`, picked by patches of `GetEconomyScript.vs`, `GetTacticScript.vs` and `Main.vs` only for the eight (`Mod_TrueRace` / `Mod_PlayerCiv`). **Engine #15** (a `Sleep` inside a script started with `AIRun` crashes the game): the economy loops are never started with `AIRun`; the three helpers the loops start (`CM_ESH_*`) have no `Sleep` (checked with `grep`: 0); the tactics `AIRun` `CM_TS_AttackAtWill` with its `Sleep`, as the game's own do. Two caveats: the lib hard-codes a 5-second window for the tactic pick (the mod's, like HD's, is 2 seconds); and *Hunting Festival* / the *Charm of Seth* family are orders of the mod: whether the engine's translation of a clone's AI maps those names to each clone's own copy was not checked in the engine (AGENTS.md says to look in the Ghidra export before claiming; not done). Not ported: `AIOSendSquad` (the engine calls it by name with no player; the mod changes a 10-minute wait to 1 minute).

**Art and sounds**: the 120 unit and 6 wall/gate entities with other bytes than HD's are renamed alone (`BHERO1.ENT_cm.XML` next to the game's sprites in the same folder: `tagCollisions` with `gameDirs`, the entity names its images relative to its folder) and the clones' classes name them; the 6 building entities are wall and gate sort offsets only. 6 `EMACE_ATTACK` sounds and four new fight sound entities (`UnitBigAxeFight`, `UnitEMaceFight`, `UnitHeavySwordFight`, `UnitSlingFight`: HD's classes do not name them, only the mod's do, so the game is not affected). 105 files of `RANDOMMAP` art and 111 of `UI` (command icons, research and upgrade pictures, infobar; names that collide with the game's are `_cm`).

**Voices**: the mod re-recorded 80 voices in English and 43 in Spanish and Italian at the game's own paths (`Local/<language>/VOICES/<UNIT>/N.WAV`), which would change the game's civilizations too. For each voice entity a clone's class names, and for the 39 folders the mod has in all three languages, the folder becomes `<UNIT>_cm` and the entity a copy of its own (`Voice<Unit>_cm.xml`) that the clones name (561 files). A clone cannot fall back to the game's English/Spanish/Italian file for a language the mod did not record, so the other 41 English folders (English only, or no clone names their entity) are **not** carried (`raw/community-mod-civs-voices.txt` lists both). The game's own voice files are not in `originals/`, so their bytes were not compared.

**Menu skin** (AGENTS.md, the one cosmetic exception): the art stays at the game's paths — `UI/Interface/MenuMod.bmp`, `MenuMod2.bmp`, `MenuModSash.bmp`, `UI/Interface/CurrentLang/AdventureDefault.BMP`, `UI/MENU/ChatButton1-3.bmp`, `Currentlang/ConquestDefault.bmp` — and the nine INIs that **place** it are patches of only the keys they changed, with `+Line` for the lists (`[MainMenu Objects] +MenuSash`, `[MPGameMenu Objects] +Back +Version`): `MAINMENU`, `MENUBACK`, `TEMPLATE`, `CONQUESTGAME`, `CONQUESTMENU`, `MPGAMEMENU`, `MPMENU`, `PREADVENTUREMENU`, `PROFILE`. The seven that only move buttons and chat boxes with no art are left out: `GSCHAT`, `INGAMECHAT`, `MAINMENU_SCROLLING`, `MPCHAT`, `SELECTMAP`, `SETTINGS`, `_GUIDE`. Ships with the usual caveats: the winner of each art file is chosen by load order or by the player in the content manager ("Use the files of …"), no `incompatibleWith`; the patches stack on top of whichever INI wins, which is not tried; the order of a `+Line` in its list (the mod has `MenuSash` first, the patch appends) is not reproduced; test conquest, options, multiplayer, lobby and the main menu. Comments at the end of a line in these INIs are cut (`validate-mod.js` says the engine does not strip them).

**Random maps**: the 14 new templates (`M02 CONTINENT TOURNAMENT.RM.XML`…`M40 RANDOMMAP.RM.XML`) and their bitmaps are additive and stay. The mod's edit of the game's own `CONTINENT.RM.XML` is **kept as a renamed template**, `DATA/RANDOMMAP/CONTINENT.RM_cm.XML` (`tagCollisions` names a file with another name than the game's by adding `_cm` before the last extension; a renamed template is a template with another name, not an edit of the game's). Whether the game offers it, and whether the 14 new ones work without the mod's `Packs/randommap.BFHP` (global, below), was not tried. `DATA/RANDOMMAP/PLACEOBJECTS.XML` (the table of counts) is global and left out.

**Adventures, scenarios and the conquest**: 12 adventures (4 Great Battles and 6 Great Challenges of the game, edited; `3_Il_Figlio_di_Ankou` and `3_Viaggio_verso_la_Gloria`), six scenarios (`00_Ludus_Martis`, `M_1vs1_Egypt`, `M_1vs1_Duels_Egypt`, `M_1vs1_FreeCivilization`, `M_2vs2_Egypt`, `M_2vs2_FreeCivilization`) and `mediterranean.BFHP`. Names that the game or another port has are renamed `(cm)` and say `(Community)` in the list (`tagCollisions`); the conquest through `tools/lib/conquests.js` **before** that: `mediterranean (cm).BFHP`, `ConquestMaps/1 - GBR Europe (cm)`, both `data=` and the menu name. They place the game's own classes (none names one of the 34 the mod adds: the build rewrote 0 maps), so they play with the game's stats, not the copies'. **The conquest's players keep the game's races**: setting a territory's `interface` to a copy's `index` needs the index, which the engine assigns, and imperivm-resurrected#45 (open question, not an engine issue opened). `Scenarios/00_Ludus_Martis (cm).BFHP` is the Community Mod's own; the Greek Mod 4.2 port ships a build of it too under the plain name (`tagCollisions` sees the collision and renames this one).

**Building exit points**: the port ships **no barracks, gym (arena), temple or village art and no `.PASS` file at all** (`find ported/community-mod-civs -iname '*.pass'` → 0): the mod's `BUILDINGS` are six wall/gate `.ENT.XML` (sort offsets, no exit points) and its `MAPOBJECTS` decor `.PASS` files are neutral map objects, left out below. The clones' barracks, temples and villages name HD's entities, so their type-2 exit points are the game's. Nothing to check; checked that nothing needs checking.

**References** (the blue-square bug): `tagCollisions` renames by file name alone and leaves broken references. `tools/lib/community-refs.js` (own, not a change to the shared one) scans every picture (`button`, `queueicon`, `icon`, `transpicon`, `image`), class entity, sound entity (`<sounds …>`), sound file of an entity and `_cm` name of the port, 2622 in all. After the rename: 95 references that did not resolve go back to the mod's own name (icons such as `STRONGHOLD DEFENSE_cm.BMP`, and the wall and gate entities, which are named by file name in every walls folder). The build stops on any that does not resolve and that the rar's own package resolved. **5 references unresolved in the rar itself are left alone** (`raw/community-mod-civs-refs-unresolved.txt`): `Sounds/entities/VoiceBDruid.xml`, `VoiceGDruid.xml`, `VoiceIEnchantress.xml`, `VoiceTEnchantress.xml` (a wrong folder in the mod's classes; the game does not find them either) and `gameres/icons/upgrades/WBreast.bmp` (HD's own). `WBreast` and `Anibal` (HD) are not touched.
