## The default commands (right click) of the units

Found by running main's `tools/lib/default-cmds.js` `check` on this port (the tool did not run it; the Greek 2.x, Legacy, MCI and Secuter ports do). A class with a `<defaultcmd>` of its own has a map of its own: its keys shadow its parent's for every target that is a kind of that key (a hero is a kind of `Unit`, so a map with `Unit` and no `Hero` attacks its own hero). **Before: 7 unit classes lacked a target of their reference, 5 shadowed.** Missing per target: `Military` 3, `ShipBattle` 2, `(ground)` 2, `Object` 1, `Sentry` 1. The same 7 are in the 1.1.0 build (nothing to do with the 1.1.1).

| Class | Reference | Lacks | Shadowed | Done |
|---|---|---|---|---|
| `KcaShaman` | HD's `CShaman` | `Military` (-> `curse`) | yes (by `Unit`) | block of the HD twin written after the class's own |
| `KegPriest` | HD's `EPriest` | `Military` (-> `cripple`) | yes | same |
| `KgeEnchantress` | HD's `TEnchantress` | `Military` (-> `curse`) | yes | same |
| `KgaGhostUnit` | `Unit` | `(ground)` | no | block of `Unit` written (the parent's was read anyway) |
| `Fisherman_cae` | `Peaceful` | `ShipBattle` | no | block written (same) |
| `CrowUnit` | the mod's `Animal` | `ShipBattle` | yes | **exempt** |
| `Mule` | `Wagon` | `(ground)`, `Object`, `Sentry` | yes (`Sentry`, by `Unit`) | **exempt** |

**The rule** is the one of the other ports (`tools/lib/caesar-defaultcmds.js`, our own lib over main's `default-cmds.js`, which is read only): the reference is the class's HD twin (`civs/*.json` `alias.classes`) when it has a map, else the nearest ancestor's (the mod's version when the mod changed it); what the class lacks is written after its own blocks, **a block the class has is never touched** (its own wins). For the priest, shaman and enchantress HD's own class repeats `Hero -> attach` next to `Military -> curse/cripple` in its map on purpose, and the mod's map (`Unit -> curse`, `Hero`, `ShipBattle`) had dropped `Military`: the target is now found in the class again. Done before the renames (the blocks carry the game's names, `tagCollisions` follows).

**Exempt, with the reason** (as MCI exempts `CarroHierro`): no `Hero` is added to either, and neither reference has one (HD's `Wagon` and `Animal`, and the mod's, have no `Hero` block), so nothing about heroes changes against HD. **`CrowUnit`**: the druids' summoned crow (`druid_crow_summoning.vs`, `CrowSummoned` derives from it), a flier; its own map (`ground -> move`, `Object -> approach`) replaces the mod's `Animal` map (`ShipBattle -> boardship`), and HD has no `CrowUnit` and no `ShipBattle` in `Animal` or `Crow`: a crow boarding a ship is not HD's and not what the mod meant. **`Mule`**: the mod's pack mule (no HD twin), `Unit -> follow`, `ShipBattle`, `Building -> unload`, `Teleport`, `Inn -> transport`; the mod's `Wagon` has no `Sentry` block, only HD's has (`Sentry -> approach`), and with the mod's own `Unit -> follow` first the mule follows a sentry: the mod's choice. If the maintainer prefers HD's wagon behaviour for either, remove it from `EXEMPT` in `tools/lib/caesar-defaultcmds.js` (the build then writes the missing blocks).

**The build runs the check and stops** (step 12c, after the renames and Greece): any unit class that still has a shadowed target and is not exempt fails it. **After: 2 classes lacking (both exempt), 0 shadowed and not exempt.** Counts and the list: `raw/caesar-mod-civs-default-cmds.txt`. ## How it is built

1. **`DATA/` goes through `tools/port-140.js`** (three-way: HD, the 1.40 files, the mod). The mod writes its class, script and command files in its own format and HD fixed files after 1.40, so a file the mod did not change is HD's, not the mod's reformatted copy: of the zip's `DATA`, 1,217 files are the mod's only, 236 are merged with HD, 436 are new, 18 have no 1.40 file to compare. **`raw/port-140/caesar-mod-civs.md` lists 242 hunks and 55 notes where the two sides touched the same lines: in each the mod's side was used and none of them was reviewed by hand.** The classes the mod wrote differently from HD but did not change against 1.40 are the mod's file as it is (elements HD has and the mod's file lacks, `projectile_class`, a `display_name`, stay as the mod ships them: that is what the mod plays with, but it is not tried here).
2. **The civilizations of the game** are cloned from HD with the mod's version of their classes and commands on top (`tools/lib/clone-civs.js`, `cloneAllOrders`); the mod's changes in the 31 base classes the clones inherit (`Hero`, `Melee`, `Unit`, `Sentry`, `RamUnit`...) are written **inside each clone**, never in HD's class.
3. **Rome.** The mod lets the player choose Republican, Imperial or Punic Rome at the town hall (`ChooseXxxRome` researches, `R*_Enable_Or_Disable_Cmd.vs` scripts that open and close the commands of each). Each branch is a civilization with the commands of its branch from the start (`tools/lib/branch.js` reads those scripts: 31, 32 and 33 commands that its scripts hide are not in `krepublic`, `kimperial`, `kpunic`); the choosing mechanism (`RTOWNHALL_CHOICE.XML`, the six scripts, `rand(3)` in the AI) is not ported. Their hero: `KrepublicHero`, `KimImperialRomanHero`, `KpuPunicRomanHero` with the hire order of the branch; **Caesar (`KreCaesar`) is the Republican branch's**, as the mod only enables "Hire Caesar" there. "Transition to Empire" is an ordinary research (it unlocks hiring Caesar), not a choice of branch: it stays. The Imperial Rome of the game (`M*`, which the mod turned into Greece) is not cloned.
4. **Greece.** The mod puts Greece in Imperial Rome's slot (race `ImperialRome`, classes `H*`, `Hhouse1-3`, `GreekHero`, walls and gates `M*`). Here its race is `kgreece` (59 classes, 20 of them city pieces) and its classes are renamed to its prefix: `HHoplite` -> `KgrHoplite`, `GreekHero` -> `KgreeceHero`, `Hhouse1` -> `Kgrhouse1`, `MWallsN` -> `KgrWallsN`, and the two commands the engine builds from the prefix, `trainpeasantkgr` and `hireheroKgr`. The text of the port that names them follows (classes, commands, scripts, AI, patches, the 8 maps of the pack that place them); a name inside a path (entity folders, pictures) stays. Its commands are `GREECE_cae.XML` (40) and patches that add its classes as sources to the game's shared commands (5). The game's AI sees it as Imperial Rome: `alias.classes` maps `MBarracks`... to the Greek ones (`alias.commands` is empty, as in the 4.2). Its random-map towns and villages are the mod's "Imperial Roman Town 1-2 / Village 1-5" (they hold the `H*` pieces): templates **`Greek Caesar Town N` / `Village N`** (7) added by a patch.
5. **Scripts** (AGENTS.md): the mod's edits of the game's behavior scripts are copies with a name of their own, `<name>_cae.vs`, and `<name>_cae_<id>.vs` where the text differs per civilization (230 files, `raw/caesar-mod-civs-own-scripts.txt`); only the clones' classes and commands point to them, the game's scripts stay the game's. The 16,286 `<method>` the clones inherit from the game's classes whose script the mod edited are written inside 767 classes. Rome's branches read `ChooseXxxRome` in some of them: the copy has the flag written in as true or false (none was left to the game's). ### Hellas: the cause (found by the maintainer's bisect, 2026-11-02) and what was done

## Methods of the mod's Unit that the clones need

**Symptom (maintainer, in game, 2026-11-05, build `1beb5c12`):** every unit trained by a `kgreece` player at the barracks, the temple or the gymnasium stayed where it appeared (a peltast in the courtyard of the barracks); the log was clean. **Not the exit point** (the file and the `.PASS` were the same as in the previous build; see the correction at *Exit points*).

**Cause, read in the engine and the files.** `barrack_train_cae.vs` (the temple uses it too; `arena_hirehero_cae.vs` does the same for heroes) ends with `u.SetCommand("advance_enter", hall)`. The mod's `Unit` declares `<method sig="advance_enter" .../>` (HD's `Unit` has `advanceenter`; the mod renamed it); the game's own scripts say `advanceenter`. `Obj::SetCommand` (`005b0c30` of the Ghidra export) cancels the object's commands and then looks the name up in the object's class: "This object does not have a '%s' command! Command not added" (to a diagnostic stub, not to `imperivm-mod.log`). A class with no such method is a unit that does nothing. The ten clones got the method because `tools/lib/clone-civs.js` (shared) writes the mod's changes to the base classes inside each civilization's classes (`decorate`: 140 classes had `advance_enter`). It follows the parent chain through the game's classes and the civilization's own only, so (1) **Greece**, the mod's own `H*` classes that this tool renames and never clones, got none of them (all 28 Greek unit and hero classes lacked `advance_enter`), and (2) a class below **a class of the mod's own that is no civilization's** (`MediumRanged`, `OldMan`, `KibSlinger`...) stopped the walk there: 14 more trainable classes (the British Javelineer, German Huntress and Teuton Archer, the Iberian Slingers, the Velit and Chariot of the three Romes...). The same happened in the 1.1.0 build.

**Before (`tools/lib/caesar-methods.js` run over the 1.1.1 build `1beb5c12`):** 399 (script, command, class) triples in 41 classes. By command: `advance_enter` 131, `guard_patrol` 68, `guard_advance` 68, `guard_engage` 68, `arrow_helper` 39, `advance_aggressive` 25. By family: `HeroMounted` 132, `MediumRanged_cae` 121, `Melee` 44, `Sentry` 30, `Ranged` 22, `Horse` 11, `ShortRanged` 11, `PeasantAmbient` 10. **The fix (the cause, in this tool's own step 3c; nothing shared edited).** `tools/lib/caesar-methods.js` `inherit` walks the whole chain of every unit class of the port (the port's classes, then the game's), parents first, and writes into the class the `<method>` elements of the mod's changes to the HD classes of that chain (`MERGED/base-changes.json`, the same table the clone step uses) whose sig the shipped chain does not have yet, the nearest ancestor's version winning (so a hero gets `hero_advance_enter.vs`, a sentry `do_nothing_obj_cae.vs`, a villager `peasant_enter_cae.vs`, a priest `peaceful_enter.vs`, a soldier `unit_advance_enter_cae.vs`, as the mod's own classes do); a method whose script exists nowhere is not written (0). It runs before the scripts step, so the `_cae` copies are used. Because it goes parents first, the methods land on the class that is the root of a family and its children inherit them at run time: **24 classes got 255 methods** (`raw/caesar-mod-civs-methods.txt`): 14 Greek (`HHoplite`, `HPeltast`, `HHypaspista`, `HToxotes`, `HMyrmidon_Javelin`, `HChariot`, `HCataphract`, `HPriest`, `HSentry`, `HVillager`, `HWVillager`, the two ambient villagers, `GreekHero`), whose 14 other classes (the three heroes' lines, the guard post sentry, the mercenary...) inherit them; `MediumRanged`, which gives them to its 10 children (British Javelineer, German Huntress and Teuton Archer, Iberian Slingers, the Velit and Chariot of the three Romes); `OldMan` (and so its two copies), `Mule`, `Fisherman` and the animals the mod ships (`BearSummoned`, `BoarSummoned`, `DeerUnit`, `HenUnit`, `CrowUnit`, `WildHorseUnit`). ### The crash with two Greek settlements and the radius (found in game, maintainer, 2026-11-02, builds `ddb501fe`..)

**Symptom:** a random map with two players of `kgreece` (or one and neutral settlements built from the Greek templates) crashed about 0.3 s after "game on screen": `gbr.exe+3fffd`, reading 0x3c, `IsStrongholdSettlement` called from `CGaikaMapBuilder::SeedSettlementGaikas` (the AI map built at the start of every game): a settlement on the map had no main building. The generator had stopped early (no `outposts created` line, no neutral players' towns in the log). 7 of ~9 games crashed with the pack; none with No profile or with the 4.2 (same templates, object for object: the same ids, positions, counts; only the class names differ).

**Cause: 18 Greek classes (8 `KgrWalls*`, 8 `KgrGate*`, `KgrVillage`) had no `radius` / `selection_radius`.** In HD every wall and gate has them (8 of each per race: 110 for the walls, 80 for `MWallsW`, 170 for the gates); the Caesar Mod's own class files have none for 48 classes whose HD class has them (HD's and the 1.40's files have them; the mod's do not), and the three-way merge of `tools/port-140.js` kept the mod's deletion. Not the cause (tested): the template (the overlay without `template` still crashed: the game's Imperial Roman city is built from `M*` classes that the DLL translates to `Kgr*`), the `wall_set` (`"Imperial Roman walls"` on the 17 Greek walls; the engine only keeps the string for the map editor's defence tree), the Caesar `<method>` scripts of `KgrTownhall` and `KgrVillage`. **The bisect:** overlay V4 (radius + wall_set + methods) and V1 (radius alone) played 7 games with two `kgreece` players, 0 crashes. V2 and V3 are not needed and are not shipped. Why a missing radius leaves a settlement without a main building was not found in the engine; the evidence is the games.

**What the build does now** (step 12a, `tools/lib/caesar-radius.js`): every class of the port whose HD class has a `radius` / `selection_radius` gets the same lines. The HD class is the key of the class's alias in `civs/<civ>.json` (`"MWallsN": "KgrWallsN"`, `"ROutpost": "KreOutpost"`), the clone tool's own record. Three rules by hand: **`KgrOutpost` <- `ROutpost`** (the alias key `MOutpost` is not in HD either; every outpost in HD has 345/350, and so have the 4.2's `HOutpost` and CGWAR's `CgrOutpost`; not tried in game), **`KgrVillage` <- `RVillage`** (the alias key `MVillage` is not in HD: the game's Imperial Roman villages are built from `RVillage`; its two lines are copied, 245/250 then 230/250, the second wins; the 4.2 and the 1.8 did the same) and **`KgrTower`: none** (`MTower` has no radius: no tower in HD has one). The classes without an HD counterpart (the mod's own: `KgrAgora`...) are not checked. Then the check runs again and **the build stops** if a class still lacks what its HD class has: `RADIUS CHECKS FAILED: KgrWallsN (DATA/CLASSES/KGRWALLSN.SC.XML) lacks them; HD's MWallsN (MWALLSN.SC.XML) has 110/110`. The list of what was added is `raw/caesar-mod-civs-radius.txt`: **48 classes**: 8 walls, 8 gates, 7 villages (`KgrVillage`, `KreVillage`, `KimVillage`, `KpuVillage`, `KcaVillage`, `KegVillage`, `KgeVillage`), 9 outposts, 12 shipyards, `Tavern2` of the three Romes and `KgaArena2`. **Tried in game: the 17 Greek classes (walls, gates, village), by the maintainer's overlay V1 (the same values). Not tried: the radius of the 30 other classes (Rome's, Carthage's, Britain's... outposts, villages, shipyards, Tavern2, Arena2), which only restores what HD's classes have.** Other ports with the same loss: see the table in the PR.

### The 1.40's parameter names in the patches of the game's AI scripts (found in game, maintainer's second test, 18:17:16)

**Five compilation errors at match creation**: `data/ai/CalcGAIKAPriority.vs (19, 28)`, `GetArmyNeed.vs (22, 27)`, `CalcMaxTake.vs (12, 40)`, `CheckMAIKA.vs (9, 33)`, `GetGAIKAStrat.vs (31, 32)`: *No matching function with name aiPlayer*. The mod's blocks (`patches/DATA/AI/*.VS`, copied into HD's script by the engine) were written for the 1.40's signature line, where the parameter is `aiPlayer`; HD's is `idPlayer`. HD's script was fine, the patched one did not compile, so **the AI of the ten civilizations could not run those five functions** (what the AI did instead was not looked at). The names check (`caesar-names.js`) missed it because it read the patch as a fragment, and a fragment declares nothing.

- **Fix** (build step 5b): for each of the 22 patches of game scripts the build reads the signature line of the mod's script (`// int, int aiPlayer, GAIKA g`) and HD's, maps the parameters **by position**, stops the build if the count, the types or the return type differ, and renames in the patch (not in its `@` directives) every parameter whose name differs. **7 had a renamed parameter**, all `aiPlayer` -> `idPlayer`: `AI/CALCGAIKAPRIORITY.VS`, `CALCMAXTAKE.VS`, `CHECKMAIKA.VS`, `GETARMYNEED.VS`, `GETECONOMYSCRIPT.VS`, `GETGAIKASTRAT.VS`, `GETTACTICSCRIPT.VS`; the other 15 (the `ESH_*`, `TSH_*`, `EvalRecruit`, `HeroSkill Default`, `MAIN`) have the same names. List and counts: `raw/caesar-mod-civs-renamed-params.txt`.
- **Checks now run on each patch applied to HD's script** (`applyPatch` of `tools/lib/script-checks.js`, the engine's algorithm): the scope check and the names check read the 22 merged scripts (HD's text plus the block) besides the port's own. Proof that the names check would have stopped it: the merged `CalcGAIKAPriority` with the 1.40 name gives 14 uses of `aiPlayer` that nothing declares; with HD's it gives none of its own (the rest it lists are the ten civilizations' ids and the mod's AI names, which the check knows from the port).
- **Not checked: a name that the mod's block declares again** that HD's script declares already (12 of the 22 do: `set`, `nHomeDist`, `own`... declared inside the block's `{ }`, so a nested scope). HD's own scripts have 10 such cases in 5 files and the log's only errors were the five above, so the compiler took them; it is not a proven rule.
