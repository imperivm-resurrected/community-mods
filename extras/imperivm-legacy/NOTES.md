Row 3, issue #20 (revisit with #37 and #38). `LegacyModInstaller_2.4.1ENG.exe`, `..ESP.exe`, `..ITA.exe` (591.2, 576.4 and 576.2 MB, ModDB; `originals/forum/imperivm-legacy-2-4-1/files/`): three Clickteam installers of a mod made for HD (loose files plus `.pak` packages and a 441.9 MB `rle.mmp`; no `.exe` or `.dll` of its own, so nothing the mod did through code is lost). ## Rebuild

The tool needs the three installers **installed**; Clickteam's format has no extractor here (`innoextract` fails; `7z e -t#` splits the chunks and loses the names). How it was done on 2026-11-01 (Linux, wine 11.0):

```bash
cd .scratch/legacy-wine     # a fresh WINEPREFIX=$PWD/prefix, WINEDEBUG=-all
wine ../../originals/forum/imperivm-legacy-2-4-1/files/LegacyModInstaller_2.4.1ENG.exe   # destination C:\legacy
wine ...ESP.exe    # C:\legacy-esp         wine ...ITA.exe    # C:\legacy-ita
```

The installer is a small window with the pages *welcome → destination → progress*; the destination was typed as above (so the 1006 MB stay inside the worktree's `.scratch/`, never in the game folder and never under `originals/`). **The first page has to be passed with the mouse** (the keys sent to the window did nothing until it had been clicked; after that `Alt+N` worked). It copies 1006 MB in about **2.5 minutes** per installer (766 MB after 114 s, all after 144 s). Nothing is run besides the installers; no registry entry or file outside the prefix is wanted.

The three installs differ only in `local/<language>.pak` (`english.pak` 39.9 MB, `spanish.pak` 19.0 MB, `italian.pak` 19.6 MB) and `update.xml`: `rle.mmp` (md5 `1cc5f6918ea4…`) and `Packs/data.pak` (`99498b8a8372…`) are the same in the three (checked with `md5sum` and `diff -rq`). So one folder is made, `.scratch/legacy-src`: the ENG install with the two other language packs copied into its `local/`. Then:

```bash
cp -al .scratch/legacy-wine/prefix/drive_c/legacy .scratch/legacy-src
cp .scratch/legacy-wine/prefix/drive_c/legacy-esp/local/spanish.pak .scratch/legacy-wine/prefix/drive_c/legacy-ita/local/italian.pak .scratch/legacy-src/local/
SDK=<imperivm-resurrected/sdk> G="<the HD game folder>" node tools/imperivm-legacy.js [id ...]     # no id: all eight
```

(`SDK` is needed in a worktree: the tools look for the SDK next to the main checkout.) The tool runs the SDK's `shrink-mod.js` on `.scratch/legacy-src` into `.scratch/legacy-pristine` (what is identical to the game stays out: 13,959 files, 306 MB; 3,308 files stay; the sprites go to `rle.mmp.tail`, 50.8 MB), puts the four hand fixes of `extras/imperivm-legacy/DATA`, `VISUALS` over it (the files whose paths were broken in the original: `BASETAVERN`, `RAMUNIT`, `RTHERMAE`, `FOG_OWNER_MARKER`) and rebuilds `ported/imperivm-legacy`. **That shrunk copy is identical, file by file, to the old build** of the previous port except those four files and `mod.json` (compared: 3,308 files). `extras/imperivm-legacy/mod.json` is copied at the end. The same build twice gives the same files (**2,457 files; md5 of the list of every file and its md5: `8dc808687e960736fa8f6190c3ea4a14`**, checked twice in a row). **That holds for the same set of ports in `ported/`**, because `tagCollisions` renames what another port also has: it was built with `cgwar`, `greek-mod-1-8`, `greek-civilization-mod` and `greek-mod-2-3`, `-2-5-3`, `-2-6-1`. The last three are rebuilt by another worktree (they are links, read only here) **while this one is built**: two consecutive builds on 2026-11-01 differed in `CHORSEMAN` / `CSHIELDS` names and a few commands because a Greek port was half rebuilt in between. For a repeatable result, wait until they stop changing and build against a copy: `cp -alL ported/<port> $PORTS/<port>` for every port with a `DATA/CLASSES`, then `PORTS_DIR=$PORTS node tools/imperivm-legacy.js` (what was done for the numbers here). **Mediterranevm (alpha), the MCI and AsvrMod were not in this worktree's `ported/`**, so a name Legacy shares with them is not renamed against them (`shared-paths` must be run again when those ports are built).

## What is a civilization's, what is not

- **A civilization's** (the eight): the mod's version of every game class of the civilization (stats, commands, costs, specials, hero skills), cloned from HD by `clone-civilization.js --all-orders` (`tools/lib/clone-civs.js`, not changed). The mod's own classes of a civilization come with it, renamed with its prefix: `?Explorer`, the eight `?FakeWalls*` (the lookouts' fake walls), `?Hero4a-c` (and `GHero5a-7c`), `GHoul`, `GAxeman2`, `GSpearman2`, `GWomanWarrior2`, `IArcher2`, `IRecon`, `EPriest2`, `MPriest`, `RAstatus`, `RCretanArcher`, `REques`, `RTriarius`, `CGuardPost`, `BHero4`... Per civilization: 94 / 76 / 63 / 72 / 72 / 74 / 71 / 70 (Gaul, Rep. Rome, Imp. Rome, Carthage, Britain, Iberia, Egypt, Germany).
- **What the mod changed in the base classes** (`Horse`, `Catapult`, `BaseMage`, `HeroGrave`, `ShipBattle`, `ShipS`, `LionFUnit`, `BearUnit`, `Deer`, `WolfUnit`, `BaseBarracks`, `BaseTavern`, `BaseTownhall`...): written **inside each clone** (155 classes of the game are changed in all), never in HD's.
- **Neutral** (nobody's, renamed `_leg` where another port has the same id): the Numidian tent `CTent` and the two units its script places by name for whoever owns it (`CHorseman`, `CSkirmisher`), the Greek garrison post `HOutpost` and its `CHoplite`, the fisherman `Fisherman`, the summons and effects (`BlackWolf*`, `Bless`, `Burn`, `Confusion`, `Famine`, `FogMarker`, `Hide`, `Inspiration`, `Poison`, `Splinters`...), the hero ships and fleet (`HeroShip`, `ShipAdmiral`, `ShipCatapult`, `ShipLembos`, `ShipRam`), `Snake`, `ConcentrationStone`, `RThermae`, `WallTarget`, `UpgradeUnitSpawner`. 51 classes with no race.
- **Scripts the mod edited** (`tools/lib/own-scripts.js`, tag `leg`): 184 of the 200 `DATA/SUBAI` scripts the mod changes are real edits (the other 16 only whitespace or comments). 185 copies `<name>_leg.vs` (and `_leg_<id>` where the class ids the script writes as text differ per civilization) that only the clones' classes and commands point to; the game's scripts are the game's. The methods the clones inherit from the game's classes whose script the mod edited are written inside each clone (12,088 `<method>` in 454 classes). The tests of the civilization in the mod's scripts (`.race == Gaul`) also accept the clone through `Mod_TrueRace`, the tests of a class (`IsHeirOf`, `Count`) and the comparisons of an object's class with a game id (`.class == "IDefender"` becomes `(.class == "IDefender" || .class == "LibDefender")`, `!=` the same with `&&`) also accept the clones' ids (97 scripts, new ones such as `MELEE_ATTACK_BONUS.VS` and `UNIT_CONVERT.VS` included); `GetPlayerRace` is left alone.

## The AI

The AI is a risk of this port (engine issue #15: `Sleep` inside a script started with `AIRun` crashes the game). Done as `tools/lib/asvr-ai.js` does (not changed), plus what Legacy needs and the library does not know (in `tools/imperivm-legacy.js`):

1. **The economy loops** `ES_Stronghold`, `ES_Village` and `ES_Shipyard`: copies `LEG_ES_*` in `[EconomyScripts]` (patch of `AI.INI`), returned by a patch of `GetEconomyScript.vs` only for the eight civilizations (`Mod_TrueRace(set.GetCentralBuilding)`). **Never started with `AIRun`.** (`ES_Shipyard` is added by the tool; the library only knows the first two.)
2. **The helpers** the loops start with `set.AIRun` (21 `ESH_*` and `TSH_RecruitArmy`; the Carthaginian army and the fleet / shipyard ones are new in the mod): copies `LEG_ESH_*`, declared in `AI.INI` and started by the copies. None of them calls `Sleep` (the game's do not either); the game's own helpers are not patched.
3. **The tactics**: the mod draws, in the first two seconds, between its tactics for Gaul (`TS_GaulTactic`, the game's `TS_GaulTactic2`), Iberia, Imperial Rome (two each), Britain and Republican Rome (one, 50%); Germany, Egypt and Carthage have none in the mod. A `GetTacticScript.vs` patch does the same for the clones (the 33/33 split of the mod is 33/34 here).
4. **Monitors**: `SquadMonitor`, `Recruiter` and the new `FleetMonitor` as copies that a `Main.vs` patch starts with the player's `AIRun` for the AI players of the eight civilizations, together with the game's other monitors.
5. **By name** (the engine calls them and they return a value): `CalcGAIKAPriority`, `GetArmyNeed`, `GetGAIKAStrat` as blocks inside the game's script that only run for the eight.
6. The AI variables (`AIV_*`) the copies use that the game's `AI.INI` lacks are declared from the mod's file in a patch (the library's regular expression stops at an underscore, so the tool declares them: `AIV_Sleep_FleetMonitor`, `AIV_FishermenTimer`...).
- **Not ported**: the tuning of `AI.INI` (values of keys the game has: for every AI), `AI/DEFENSIVE` and `AI/_TEUTON` (profiles), `AIOSendSquad` and `EvalRecruit` (the engine calls them with no player to scope them by), the outposts' loops `ES_OutpostSellFood` / `ES_OutpostSellGold` (a global change of outposts), `GS_KillEnemies`.
- **Unit limits for the new units** (`AIV_MaxRAstatus`, `AIV_MaxRCretanArcher`, `AIV_MaxRTriarius`, `AIV_MaxREques`...): they name the mod's ids; the clones' own ids are `Lro...`. The copies read the variable by the mod's name, which the game's AI.INI lacks and the patch declares; whether the clone's units count against it was not checked.

- **Exit points of the buildings** (`tools/lib/legacy-exits.js`, `raw/imperivm-legacy-exit-points.txt`). **Not checked geometrically, and why:** the point of an entity (`<point type="2">`, screen offsets) is not mapped to a cell of the `.pass` (a diamond) anywhere the tool can read; a search of 2,401 affine maps over the game's own 276 type-2 points put at most 82% on a free cell and the best ones disagree, so a test of "lands on a free cell that leads out" would be a guess and is not done. What is checked instead: for each building the port ships, its set of type-2 points **and** the bytes of its `.pass` against every building of the game. **No barracks, gym or village is shipped.** The two temples (`MTEMPLE`, `RTEMPLE` AS/W) and the arenas (`MARENA`, `RARENA` AS/W) have the points and the `.pass` of the game's own (25 of 33 buildings do). The **8 that do not**, to look at in game (units stuck inside a building = its exit is closed in): `CGUARDPOST` (its own `.pass`), `GGUARDPOST` AS/W (points `-171,-161`, `261,134`), `HOUTPOST` (`-100,130`, `100,130`), `RHOUSE02` AS/W (`-120,115`), `SHIPYARD 4` AS/W (`-108,-15`, `201,-174`). The Greek fix (moving `(-32,-50)` to `(-16,-50)`) was **not applied**: no `.pass` of this port has that dead end that the tool can see, which is not the same as having been looked at.
- **Scripts** (the tool stops on a problem): every copy has the parens, braces and brackets of the mod's script it comes from and no `Mod_TrueRace` without an object (429 scripts); the 12 patches of the game's scripts are applied with the engine's algorithm, each block balanced and the result with the game's balance; 926 class strings resolve to a class of the game or of this port. No unprefixed hero or class string is left outside `if(false)`. The mod's scripts had no stray `}`.
- **Prefixes**, **set name** and **no `incompatibleWith`**: above.
