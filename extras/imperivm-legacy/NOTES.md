## Rebuild

The tool needs the three installers **installed**; Clickteam's format has no extractor here (`innoextract` fails; `7z e -t#` splits the chunks and loses the names). How it was done on 2026-11-01 (Linux, wine 11.0):

```bash
cd .scratch/legacy-wine     # a fresh WINEPREFIX=$PWD/prefix, WINEDEBUG=-all
wine ../../originals/forum/imperivm-legacy-2-4-1/files/LegacyModInstaller_2.4.1ENG.exe   # destination C:\legacy
wine ...ESP.exe    # C:\legacy-esp         wine ...ITA.exe    # C:\legacy-ita
```

The installer is a small window with the pages *welcome → destination → progress*; the destination was typed as above (so the 1006 MB stay inside the worktree's `.scratch/`, never in the game folder and never under `originals/`). **The first page has to be passed with the mouse** (the keys sent to the window did nothing until it had been clicked; after that `Alt+N` worked). It copies 1006 MB in about **2.5 minutes** per installer (766 MB after 114 s, all after 144 s). Nothing is run besides the installers; no registry entry or file outside the prefix is wanted.

The three installs differ only in `local/<language>.pak` (`english.pak` 39.9 MB, `spanish.pak` 19.0 MB, `italian.pak` 19.6 MB) and `update.xml`: `rle.mmp` (md5 `1cc5f6918ea4…`) and `Packs/data.pak` (`99498b8a8372…`) are the same in the three (checked with `md5sum` and `diff -rq`). So one folder is made, `.scratch/legacy-src`: the ENG install with the two other language packs copied into its `local/`. Then:

```bash
cp -al .scratch/legacy-wine/prefix/drive_c/legacy .scratch/legacy-src
cp .scratch/legacy-wine/prefix/drive_c/legacy-esp/local/spanish.pak .scratch/legacy-wine/prefix/drive_c/legacy-ita/local/italian.pak .scratch/legacy-src/local/
SDK=<imperivm-resurrected/sdk> G="<the HD game folder>" node tools/imperivm-legacy.js [id ...]     # no id: all eight
```

`SDK` and `G` default to the SDK next to the main checkout (found from any worktree) and to the Steam folder of the HD game; set them if yours are elsewhere. The tool runs the SDK's `shrink-mod.js` on `.scratch/legacy-src` into `.scratch/legacy-pristine` (what is identical to the game stays out: 13,959 files, 306 MB; 3,308 files stay; the sprites go to `rle.mmp.tail`, 50.8 MB), puts the four hand fixes of `extras/imperivm-legacy/DATA`, `VISUALS` over it (the files whose paths were broken in the original: `BASETAVERN`, `RAMUNIT`, `RTHERMAE`, `FOG_OWNER_MARKER`) and rebuilds `ported/imperivm-legacy`. **That shrunk copy is identical, file by file, to the old build** of the previous port except those four files and `mod.json` (compared: 3,308 files). `extras/imperivm-legacy/mod.json` is copied at the end.

**The other ports (what the names are renamed against, and the repeatability).** `tagCollisions` renames what another port also has, so the result depends on which ports exist. The tool reads them like the Caesar, MCI, Secuter and Community ports do, from anywhere: the main checkout's `ported/` (the parent of the git common dir), the `ported/` of the worktrees under `MAIN/.wt/` and of `MAIN/../wt-*` (only the ports of its required list), and this worktree's. Of a name found in several places it takes the build that has `civs/` (the pre-#37 ports of the main checkout and of git do not; a fresh checkout gives their files the newest dates, which chose them in a first attempt), then a worktree's before the main checkout's and this one's, then the newest. It **writes what it used to `raw/imperivm-legacy-others.txt`** (name, files, last change, a fingerprint of the list of paths and sizes, path, the older builds it did not use: 21 ports on 2026-11-02) and **stops** if a port of the list is missing (`cgwar`, `greek-mod-1-8`, `greek-civilization-mod`, `mediterranevm-alpha`, `mci`, `community-mod-civs`, `secuter-fun-mod`, `secuter-fun-mod-grecia`, `caesar-mod-civs`, `mediterranevm-3-6`, `greek-mod-2-3`, `-2-5-3`, `-2-6-1`, `asvrmod-vii-civs`, `nuclear-fazioni-equilibrate`) or if one changed in the last 90 seconds (its owner may be rebuilding it: it happened three times while this was done, with the Greek 2.x ports; wait and run again). `LEGACY_NO_OTHERS=1` builds with what is found (the bytes then depend on it). **Same bytes from three places** (2026-11-02, commit before the verifier fix, same inputs): twice in `.wt/imperivm-legacy-37-38` and once in a clean worktree **outside** `.wt/` (`git worktree add --detach`, `originals` linked, `LEGACY_SRC` pointing to the installs): 2,440 files, md5 of the list of every file and its md5 `38f406b9cacded7e669d72b8ee3b2e42` in the three, and the same list of ports with the same fingerprints. After the verifier fix (below) the same build twice in `.wt/` gives `4d623b9092771b4eb79b7a4a4c4f89e3`; with `redistributable: true` (2026-11-02) **`d5342462002e1fb3ccc8290d6a989459`**, twice in `.wt/` and once in the clean worktree. It changes if another port is rebuilt with other bytes; the list in `raw/` says against what.

Per civilization: 94 / 76 / 63 / 72 / 72 / 74 / 71 / 70 (Gaul, Rep. Rome, Imp. Rome, Carthage, Britain, Iberia, Egypt, Germany).
- **What the mod changed in the base classes** (`Horse`, `Catapult`, `BaseMage`, `HeroGrave`, `ShipBattle`, `ShipS`, `LionFUnit`, `BearUnit`, `Deer`, `WolfUnit`, `BaseBarracks`, `BaseTavern`, `BaseTownhall`...): written **inside each clone** (155 classes of the game are changed in all), never in HD's.

The tests of the civilization in the mod's scripts (`.race == Gaul`) also accept the clone through `Mod_TrueRace` (58 scripts), `IsHeirOf` also names the clone, and the comparisons of an object's class with a game id (`.class == "IDefender"`, also with an indexed receiver `ol[i].class` and the arena's variable `class`) become `(.class == "IDefender" || .class == "LibDefender")` (`!=` the same with `&&`): the game's id stays because the object may be a game civilization's. **`Count(player, "GArcher")` is left as it is, on purpose** (the first build added a second `Count` of the clone's id): the engine's `CVXArmy::GetClassCount` hook (`src/game/civai.cpp`, `HookClassCount`) already adds the classes of `alias.classes` to the base's name for every civilization with `ai: true`, so the second `Count` counted the units twice; the same file hooks `IsDerivedFrom` and `IsKindOfName`, which makes a clone's unit an `IsHeirOf` of its base (the `IsHeirOf` alternatives are redundant, not wrong). Read in the source, **not tried**.

## The AI

The AI is a risk of this port (engine issue #15: `Sleep` inside a script started with `AIRun` crashes the game). Done as `tools/lib/asvr-ai.js` does (not changed), plus what Legacy needs and the library does not know (in `tools/imperivm-legacy.js`):

1. **The economy loops** `ES_Stronghold`, `ES_Village` and `ES_Shipyard`: copies `LEG_ES_*` in `[EconomyScripts]` (patch of `AI.INI`), returned by a patch of `GetEconomyScript.vs` only for the eight civilizations (`Mod_TrueRace(set.GetCentralBuilding)`). **Never started with `AIRun`.** (`ES_Shipyard` is added by the tool; the library only knows the first two.)
2. **The helpers** the loops start with `set.AIRun` (21 `ESH_*` and `TSH_RecruitArmy`; the Carthaginian army and the fleet / shipyard ones are new in the mod): copies `LEG_ESH_*`, declared in `AI.INI` and started by the copies. None of them calls `Sleep` (the game's do not either); the game's own helpers are not patched.
3. **The tactics**: the mod draws, in the first two seconds, between its tactics for Gaul (`TS_GaulTactic`, the game's `TS_GaulTactic2`), Iberia, Imperial Rome (two each), Britain and Republican Rome (one, 50%); Germany, Egypt and Carthage have none in the mod. A `GetTacticScript.vs` patch does the same for the clones (the 33/33 split of the mod is 33/34 here).
4. **Monitors**: `SquadMonitor`, `Recruiter` and the new `FleetMonitor` as copies that a `Main.vs` patch starts with the player's `AIRun` for the AI players of the eight civilizations, together with the game's other monitors.
5. **By name** (the engine calls them and they return a value): `CalcGAIKAPriority`, `GetArmyNeed`, `GetGAIKAStrat` as blocks inside the game's script that only run for the eight.
6. The AI variables (`AIV_*`) the copies use that the game's `AI.INI` lacks are declared from the mod's file in a patch (the library's regular expression stops at an underscore, so the tool declares them: `AIV_Sleep_FleetMonitor`, `AIV_FishermenTimer`...).
- **Not ported**: the tuning of `AI.INI` (values of keys the game has: for every AI), `AI/DEFENSIVE` and `AI/_TEUTON` (profiles), `AIOSendSquad` and `EvalRecruit` (the engine calls them with no player to scope them by), the outposts' loops `ES_OutpostSellFood` / `ES_OutpostSellGold` (a global change of outposts), `GS_KillEnemies`.
- **Unit limits for the new units** (`AIV_MaxRAstatus`, `AIV_MaxRCretanArcher`, `AIV_MaxRTriarius`, `AIV_MaxREques`...): they name the mod's ids; the clones' own ids are `Lro...`. The copies read the variable by the mod's name, which the game's AI.INI lacks and the patch declares; whether the clone's units count against it was not checked.
- **Where a clone's player gets its race (the AI)**: read in the engine (`src/game/civai.cpp`, `src/game/civs.cpp`): `Obj::race` (`HookObjRace`) is mapped to the base **only for objects of an AI player** of a civilization with `ai: true`; `GetPlayerRace` (`HookGetPlayerRace`, `civs.cpp`) is mapped to the base **only for a `variant`**, and a clone here is not one, so it returns the clone's own race (>= 10); `GetRaceStrPref(race)` of a race >= 10 returns the clone's prefix (`Lga`), not `G`. Therefore `GetPlayerRace(idPlayer)` in `LEG_ESH_BuildFleet.VS` (line 28), `LEG_ESH_BuildAdmiralShip.VS` (18) and `LEG_ESH_NeedTechShipyard.VS` (8, with `GetRaceStrPref`) never matched `RepublicanRome`, `ImperialRome`, `Egypt` or `"G"`/`"R"`/`"C"`...: every clone built the generic ship and researched no shipyard tech. They now read `set.GetCentralBuilding.race` (the building's race, which the AI hook maps to the base; the game's own `ESH_Market` reads it so). The build stops if an AI script still calls `GetPlayerRace`. **Not tried.**
- **Class comparisons in the AI**: a string comparison (`b.class == "COutpost"`, `LEG_ES_Village.VS`) is not one of the engine's hooks, so the AI scripts also get the clones' ids in each comparison (as the other scripts do); `Count` and `IsHeirOf` are the engine's. The AI's `class = "GTridentWarrior"` variables (`LEG_ESH_ArenaUnits.VS`) are only used in `Count(AIPlayer, class)` and become the clone's id (a plain count of that class: the engine's sum is for the base's name); `TS_AttackAtWill` asks `ObjsInCircle` for `IOutpost` and `BOutpost` and gets the clones' too (`Union`). **Not tried.**
