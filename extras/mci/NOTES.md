# Mod Comunidad Imperivm (MCI) 9.0, as "MCI Comunidad 9.0"

Row 7, issue #18 (revisit with imperivm-resurrected#37 and #38). `MOD Comunidad Imperivm 9.0.zip` (366 MB, forum t262, `originals/forum/t262/files/`; the same download has `MLR + MCI v8.0.zip`, 71 MB, an older release that is not used). 1,104 loose files for a 1.40 install (`DATA`, `UNITS`, `UI`, `SOUNDS`, `OUTLINES`, `RANDOMMAP`, `CURRENTLANG`, `Adventures`, `Scenarios`, `movies`, `music`, a 388 MB `rle.mmp`) and **no executable**. It is built on JVLIVS CAESAR's La Reconquista (row 8, `extras/la-reconquista-2010/`).

**Permission:** the authors' permission was granted to the maintainer, per the maintainer, 2026-11-02. That is the maintainer's statement (no name, date of the answer or link was given); there is no document to quote. The *Permission* column of `docs/MODS.md` row 7 says so. **Licence:** the zip has no licence file and its `DATA/COPYRIGHTS.TXT` has the same bytes as the game's, so it says nothing about the mod; **no licence name is recorded** and none is invented. `redistributable` stays `true`. `authors` in `mod.json` is the credits list of the forum post plus `Villoh (port)`. Rows of `docs/AUTHORS.md` (the contact table, filled by hand) exist for Camarada, Poliko, JVLIVS CAESAR, moonson, Frodo45127, frikypani, JNXF and El Jüsticiero Misteryoso; none for Comunidad Imperivm or zeloslaw as MCI authors (zeloslaw has a row for GBR Tactics). They were not edited: their *Contacted* / *Answer* columns record contacts with each author, and the permission is the maintainer's statement, not an author's answer.

## What changed against the old port

The old port (`tools/port-140.js` alone, no `NOTES.md`) put 355 files at the game's paths: 173 class ids the game also has, 7 civilizations and 20 base classes changed for every player, 86 of the game's behavior scripts and 26 AI files replaced, the game's `CONST.INI`, `ITEMS.XML`, `SKILLS.INI`, `FORMATIONS.XML`, `BONUS.XML`, menu INI and random map object list replaced. Now:

- the mod's version of each of the game's civilizations is a clone from HD (`tools/lib/clone-civs.js`, `cloneAllOrders`), and the base-class changes (`Unit`, `Hero`, `Ranged`, `Melee`, `Outpost`, `BaseVillage`, `BaseTownhall`...: 646 elements in the Gaul clone, 291 to 561 in the others) are written **inside each clone's own classes**, never in HD's;
- the scripts the mod edited are copies of their own (`_mci`) that only the clones point to, or blocks inside three of the game's scripts that only run for the clones;
- the shared tables only contribute what the mod **adds**, as patches;
- everything global is in the **ruleset layer** `rulesets/mci/` of the same package (not mounted by default: the host picks it in *Create room* → *Rules*), see *The ruleset layer*; the civilizations stay in the root.

`node tools/shared-paths.js mci`: see *Independence check*.

## Rebuild

After the build, `node tools/audit-completeness.js mci --strict` must pass (UNCLASSIFIED 0, every GLOBAL row carried in `rulesets/mci/`); `mci.js` runs the layer step itself and stops if not (`MCI_LAYER_OPEN=1` skips the stop).

```bash
G="$HOME/.local/share/Steam/steamapps/common/Imperivm - Great Battles of Rome HD" SDK=<imperivm-resurrected>/sdk node tools/mci.js [id ...]     # no id: all eight
```

It unpacks the zip into `.scratch/mci-unpack` (inside the worktree, git-ignored; nothing is written under `originals/`), runs `tools/port-140.js` on it into `.scratch/mci-pristine` (HD + 1.40 + mod, three-way; `raw/port-140/mci.md` lists 0 conflicts to check by hand), copies that into `ported/mci` (git-ignored) and does the rest. `extras/mci/` is the input of `port-140.js` as before: **30 files the mod and HD both changed, merged by hand** (`DATA/CLASSES/UNIT.SC.XML`, the six hero classes, `DATA/COMMANDS/{ARENA,GBARRACKS,VILLAGE}.XML`, the scripts `UNIT_ON_KILL.VS`, `UNIT_ATTACK.VS`, `HERO_MOVE.VS`... that keep the HD guard post, gold selling, kill statistics and sentry guards next to the MCI's tributes, stances and veterans; see `docs/BIG-MODS.md`) and `Adventures/Gartomix.bmp`. They are the **mod's version of the game's classes and scripts that the clones are made from**: none of them is shipped at the game's path. `mod.json` is the only file of `extras/mci/` copied into the port at the end. The same build twice gives the same files (1,347 files before the layer, 1,460 with it: md5 of the whole list identical twice on 2026-11-10, built in a worktree against the ports of the main checkout, which now include Asvr, Caesar and Community: 161 root files differ from the 2026-11-04 build only because more of their names are tagged `_mci`; checked with md5; the five lists in `raw/mci-*.txt` too). **The result does not depend on where it is built:** the ports it compares its names with are read from the main checkout (the parent of the git common dir) and from the worktree's own `ported/`, and the build **stops** if `cgwar`, `greek-mod-1-8`, `greek-civilization-mod`, `mediterranevm-alpha` or `imperivm-legacy` is in neither (`MCI_NO_OTHERS=1` builds without them, with other names). Proved by building the same commit in the worktree under `.wt/` and in a clean detached worktree in `/tmp` (its own `ported/` has only the tracked ports): the md5 of all 1,352 files and of the four lists are identical (a run in the main checkout itself was not possible: it would overwrite its old `ported/mci` and it does not have this branch). Libraries: `tools/lib/mci-refs.js` (the picture, sound and path post-pass, below), and `clone-civs.js`, `own-scripts.js`, `asvr-ai.js`, `asvr-inline.js`, `script-checks.js`, `ported-patch.js`, **unchanged**.

## What is a civilization's, what is not

- **A civilization's:** the mod's version of every game class of the civilization (stats, costs, specials, hero skills, the sentries' guard), the orders (`cloneAllOrders`: every order the clone shares with its base is its own copy with the mod's costs and texts: `generals school Igaul`, `MercenariesGuild Igaul`, `auto_call_gpeasants_start Igaul`...), and the mod's new classes of its race: the long bowman, the captain, the outpost guard, the ship and the transport, the extra heroes `?Hero1c..8b`, the second sentry `?Sentry2`, and for the Germans the `RebelJavelinThrower`, `RebelLiberatus` and the `GVillagerRescue` of the Gauls.
- **Classes the mod gave to one race and several civilizations train** (`asBase`, `neutral` in `tools/mci.js`; read from the Mercenaries Guild and the arenas): `EHOPLITA` (race Egypt) is hired by Gaul and Rome, `Hipatista` (race Carthage) by Imperial Rome and Iberia, `PINMORTAL` (race Egypt) by Britain and Carthage, `CMERCENARIO` (race Carthage) by Egypt and Germany, `TaxCollector` (race ImperialRome) by both Romes. Each of those civilizations has its own copy with its base's race (`IgaEHOPLITA`, `IroEHOPLITA`, `IimHipatista`...); the civilization whose race names the class and does not hire it has none.
- **The mod's own neutral classes** (nobody's), kept with the tag `_mci`: `CaptainOutpost`, `LongRanged`, `Piked`, `SentryOutpost` (bases of the captain, the long bowmen and the outpost guards), `ShipTransport`, `ShipSFishing`, `TraderRescue`, `IronMine`, `Main` (a tent the random map places) and `CarroHierro` (the iron cart; nobody else has the id). The tag is there because La Reconquista 2010 (which the MCI is built on) and GBR Tactics define the same ids (below).
- **Orders on the game's base classes** (tribute, burn, stances `pasivo`/`defensivo`/`agresivo`/`sed_de_sangre`, `retreat_notai`, gate levels, `great_charge`): their sources become the classes of this port under the base class (37 orders; the game's own `Unit`, `Hero`... never get them): `patches/DATA/COMMANDS/{UNIT,VILLAGE,OUTPOST,CATAPULT,SHIP,TTENT}.XML` and the commands of the clones.
- **Items** (`patches/DATA/ITEMS.XML`): the 82 items the mod adds (the hero ranks `Captain`, `Officer`, `General`, `Leader`; the armoury and assassin items; the `Meat` and `HeroFavoriteUnit` items...), 16 item scripts, icons (`UI/ICONS`, `UI/FAVOURITE`).
- **Other additions as patches:** `CONST.INI` (17 keys the game lacks), `FORMATIONS.XML` (4 formations: `Hilera`, `Retaguardia`, `Cucaracha`, `Alas Del Infierno`; shared with the Secuter mods, see *Overlap*), `BONUS.XML` (6 bonuses of the clones' spearmen and javelin men against horses), `RANDOMMAP/PLACEOBJECTS.XML` (5 lines: the Main tent and the iron mine in the `stonehenge` blocks).
- **Sounds, art, music:** 59 sounds, 291 interface pictures (command icons, favourites, help), the sprites of the new units (`UNITS/{CMERCENARIO,EHOPLITA,HIPATISTA,PINMORTAL}_mci`: 48 standalone `.rle`, no `rle.mmp.tail`, so no graphics-tail conflict with the 4.2 or Imperivm Legacy), the entities of the 7 second sentries and of 8 game units whose animation the mod edited (the clones use those; they are in the game's folders under `<name>.ENT_mci.XML`), the `Hipatista` voices, 8 music tracks (`GBR_TRACK_8..15_mci.ogg`), 6 random-map templates and their previews.
- **The mod's maps:** 9 scenarios and 10 adventures (see *Maps*).

## Scripts

`tools/lib/own-scripts.js` (tag `mci`): **69 scripts copied** as `<name>_mci.vs` (and `_mci_<id>` where the class ids the script writes as text differ per civilization: 179 files in `DATA/SUBAI`, the list in `raw/mci-own-scripts.txt`), which only the clones' classes and commands point to; the game's scripts are the game's. The methods the clones inherit from the game's classes whose script the mod edited (`unit_attack`, `unit_engage`...) are written inside each clone (8,202 `<method>` in 567 classes). The mod wrote its civilization tests as `.race == Gaul`; for a clone the race is the clone's own, so each test also accepts the clone (`Mod_TrueRace`), 33 scripts. `GetPlayerRace` is left alone.

Three behaviors the clones inherit and the mod edited cannot be copies (a class lists 8 at most and the same path counts once): `arena_behavior.vs`, `outpost_behavior.vs`, `village_behavior_givefood.vs` go as one block per civilization inside a **patch of the game's script** (`patches/DATA/SUBAI/`, `tools/lib/asvr-inline.js`), at the first line of code, `if (Mod_TrueRace(This) == Igaul) { ... return; }`. The game's civilizations never enter a block. **A compilation error in one of these three patches stops the script for every civilization.** The other inherited behaviors the mod edited (`hero_skill_behaviour.vs`, `stamina_counter.vs`, `gate_patrol.vs`, `outpost_behavior_guard.vs`, `townhall_behavior_guard.vs`, `settlement_behavior_ambient.vs`, `townhall_autotrain.vs`, `townhall_sentries_control.vs`, `wall_patrol.vs`) stay the game's: *Not ported* below.

**Checks the build makes** (`tools/lib/script-checks.js`, **the build stops** on any failure): every copy has the parens, braces and brackets of the mod's script it comes from and no code after a `return`; each of the 9 patches of the game's scripts is applied to HD's script with the engine's algorithm (`PatchScriptText`) and the result is balanced; 394 class ids written as text in scripts are classes of the game or of this port. Since the review of PR #45 the build also runs the **names check** (`tools/lib/mci-names.js`, the one of the Greek 2.x branch under another name): every script the port's classes, commands or AI start (305 read, 26 that nothing points to were not read) may only call or compare names that are a variable or parameter of the script, a member, a function, type or constant the game gives scripts (`sdk/game-functions.txt`), a special, an AI variable or script, an order, or a class of the game or of the port, and every script a class, a command or a string names must exist; **0 problems** in this build, and the build stops on any. It cannot see the type of an expression, the signature of a call, the `Mod_*` functions or a name a string builds at run time. **These are still not a compiler.** An undeclared variable, a wrong type or a wrong argument count pass them. The test is `Logs\imperivm\imperivm-mod.log`, `compilation error`.

**A bug found in game in the sibling Community Mod port, and fixed here (2026-11-02).** The tests the mod wrote as `.race == Carthage` are rewritten as `(.race == Carthage || Mod_TrueRace(X) == Icarthage)`, and the generator wrote X = `This` for every script whose header did not start with an `Obj` parameter. A **group verifier** (`//bool, ObjList objs, str OUT reasonText`) has no `This`: its object is the local `Building this;`. `Mod_TrueRace(This)` there is "No matching function with name This", the script does not compile, and every command whose groupverifier it is fails to verify. In this port it was one script, `DATA/SUBAI/verify_research_mci.vs` line 197 (the Specialization test of the Egyptian/Carthaginian research commands); the generator now writes the local (`tools/lib/mci-receivers.js`, `receiverOf`). Diff of the built file: `- if ((.race==Carthage || Mod_TrueRace(This) == Icarthage) && name=="Specialization")` → `+ ... Mod_TrueRace(this) == Icarthage ...`. **The names and script checks did not see it** (`This` is a name the game knows), so the build now also runs `checkReceivers`: in every script of the port (217) and in each patch (against the header and declarations of the game's script it patches) every `This` used must be a parameter or a local, and so must the object given to every `Mod_TrueRace` / `Mod_PlayerCiv`; **0 problems**, the build stops on any. Uses in this build: `Mod_TrueRace(This)` x78, `(u)` x37, `(set)` x16 (all `set.GetCentralBuilding`), `(this)` x1, `Mod_PlayerCiv(idPlayer)` x16, `(AIGetPlayer)` x8 (a game function, allowed by name), `(set)` x8. The other receiver forms: the `!=` branch uses the same receiver as the `==` one (same function); the scripts with another first object (`Obj me`, `Obj owner`, `Obj this`) already used it; bare `.player` is left as the mod wrote it (it compiled in 1.40 and in the other scripts; I found no case where the generator wrote it). It still cannot see the type of the receiver (a `Mod_TrueRace(u)` with `u` a `Unit` is accepted) or whether a name is spelt as the game wants: the game's log is the test.

## The AI

13 scripts as `MCI_*` copies, started only for the clones: the economy loop `ES_Village` (picked by a patch of `GetEconomyScript.vs`; **never started with `AIRun`**: it calls `Sleep`, and a `Sleep` inside a script run by `AIRun` crashes the game, engine #15), the helpers `ESH_BuildArmy` and `ESH_Market` (no `Sleep`, they do their work and return, as the game's do; they start other scripts with `AIRun` as HD's own `ESH_BuildArmy` does), `SquadMonitor` (started by a patch of `Main.vs` with the player's `AIRun` like the game's other monitors; it sleeps, HD does the same), `TS_AttackAtWill` and the eight tactics `TS_GaulTactic2`, `TS_IberianTactic2`, `TS_GermanyTactic2`, `TS_EgyptTactic`, `TS_BritishTactic`, `TS_CarthageTactic2`, `TS_RRomeTactic`, `TS_MRomeTactic2` (picked per civilization by a patch of `GetTacticScript.vs` in the first 5 seconds, the mod's own value). What the engine calls by name and returns a value (`CalcGAIKAPriority`: 70 % instead of 100 %, `GetArmyNeed`: timings, `TSH_ArenaRecruit`) is a block inside the game's script that only runs for the clones (`Mod_PlayerCiv`). `ES_Stronghold` and the other helpers are the game's: the mod did not edit them.

**Does the AI of an `ai: true` civilization see the base? Evidence** (the review of PR #45 asked; the AI scripts name base orders and compare the base race): `sdk/civilizations.md`, *The AI*, says the game's AI scripts "see the base" and that the orders they ask for by name are "mapped to your civilization's, according to `alias.commands`, only on objects of an AI of your civilization". The engine source says the same (`imperivm-resurrected/src/game/civai.cpp`): `HookObjRace` returns the **base** for `Obj::race` of an object whose class has a mod race (>= 10) when its owner is an AI player and the civilization has `ai`; `TranslateArg` rewrites the order name that 16 natives receive, through `aliasOrders` (`Obj::ExecCmd`, `Obj::CmdCount`, `Building::Research`, `IsResearched` and `IsResearching` in their settlement and player forms, `Settlement::CanAfford`, `CanAfford(n)`, `MaxAffordCount`, `CanResearch`, `Research`, `ReserveFor`, `CheckTechBudget`, `FindResearchLab`, `TSResearch`); `IsDerivedFrom`, `IsKindOf` and the class count see the clone as its base. So `nRace = set.GetCentralBuilding.race` in `MCI_ESH_Market` is the base (`Gaul`...), `GetRaceStrPref(...) + "Tribute"` builds `GTribute`, `set.FindResearchLab("GTribute")` is rewritten to the clone's order, and `bOutpost.race == Carthage` in `MCI_ES_Village` is true for an outpost of an AI `icarthage`. **Checked against this build's `civs/*.json` `alias.commands`:** the order each civilization's market script asks for by base race is aliased: `GTribute`, `BTribute`, `CTribute`, `ETribute`, `ITribute`, `MTribute`, `RTribute`, `TTribute` (one per civilization); `Free Beer` (Gaul), `Free Wine` (Rome, Imperial Rome), `Free Trade` (Carthage), `Free Drinks` (Iberia), `Gambling` (Britain), `GrainTrade`, `Hecatomb`, `BuySlaves`, `ReligiousFeast` (Egypt), `TGrainTrade`, `TReligiousFeast`, `TFoodTax` (Germany). **What this does not cover:** an order name given to a native that is not one of those 16 (the `tribute_food` keys `ES_Village` writes with `EnvWriteString` are the tagged name `tribute_food (mci)` in the copies, consistent with the order, but not translated by the engine); an object of a human or neutral player (its `.race` stays the clone's: a test on an enemy human clone's building is false); the costs the AI reads before paying are the base's (`civilizations.md`). **Not tried in game:** an `(MCI)` AI building, researching or trading.

Not ported: the tuning of `AI.INI` (27 values of keys the game has, global, below), `AI/DEFENSIVE/` (the mod's profile), `AIOSendSquad`, `GS_KillEnemies`, `GSH_SynchApproach`, `GS_Capture` (the engine picks the strategy; log lines and constants).
