# Porting a mod

**English** · [Español](es/PORTING.md)

1. **Author.** Try to reach the author (Discord, see [AUTHORS.md](AUTHORS.md), or forum) and note the answer in the *Permission* column. If they cannot be reached, publish with full credit; remove it if they ask (see [Authors and removal requests](../README.md#authors-and-removal-requests)). If the license allows it (e.g. CC BY-SA), there is no need to ask, but the author must be credited.
2. **Download**: `node tools/download-discord.js` (Discord attachments) or `node tools/download-forum.js` (forum, Mega, MediaFire, ModDB…).
3. **Port**, with the tool for its *Type*:

   | Type | What the mod is | Tool |
   |---|---|---|
   | *wrap* | A map or adventure, untouched | `node tools/wrap-map.js [channel/]<slug>` (Discord), `forum/t<topic id>`, or `pack:<pack>/<map> --author "…"` for one map of a downloaded pack (see below) |
   | *reduce* | A mod with whole `.pak` packages | `node shrink-mod.js <original> "<game>" ported/<id> --id <id> …` (SDK) |
   | *rewrite* | A loose-file mod made for 1.40 | `node tools/port-140.js <folder> ported/<id> --id <id> …` (see [Mods made for 1.40](BIG-MODS.md#mods-made-for-140)) |
   | *wrap · requires imperivm1-legacy* | A map with Imperivm I classes | `node tools/imperivm1.js add <map.bfhp>`, then `wrap-map.js` |

4. **`mod.json`**: `"authors": ["<Original author>"]`; add `"<your name> (port)"` only for real adaptation work (*reduce*, *rewrite*). Plus `category` (`Scenarios`, `Adventures`, `Conquests`… as on GameBanana), `tags` in the SDK's form (`Players: 2-4` for scenarios, 2 to 8; `Language: Spanish` for adventures; `Type: <category>` for anything else the mod also is) and `"redistributable": true` (the room host can send it; `--no-redistributable` if the author asks not to).
   **Civilizations are independent, 100%.** The game's 8 are never modified: a mod that adds a civilization, or changes one (stats, sprites, sounds, behaviors, commands), ships it as **its own civilization next to the game's** ("Gauls" is HD's, "Gauls (Greek Mod 1.8)" the mod's), with its own `civs/<id>.json` (`id`, `race`; the prefix is derived from the id and the game assigns the index, imperivm-resurrected#37) and its own class, entity, command and script names. What is not a civilization's (`const.ini`, `items.xml`, game scripts…) goes as a patch that adds only its part, never as a file in the same path as another mod's. So any civilization mods can be combined. `incompatibleWith` between them is only a temporary state for an unfinished port. Rules and the check to run: [AGENTS.md](../AGENTS.md#civilizations-are-independent); letters and indices in use: [Civilization mods](CIVILIZATIONS.md).
5. **Validate** (from the SDK): `node validate-mod.js <folder> --game "<game>" --data originals/game-data/DATA`.
6. **Test** in the game (`mods\`, Additional content) and check `Logs\imperivm\imperivm-mod.log`. `LogFiles=1` under `[Debug]` in `imperivm-mod.ini` logs every file the game opens.
7. **Publish**: zip the folder, *Add → Mod* on GameBanana, same category, tags and version. Under **Credits**, the author as *Original Creator*; you as *Porter* only for *reduce*/*rewrite* mods (for *wrap*, being the submitter is enough). Link the original thread.
8. **Update the tables**: `node tools/sync-table.js` sets *Type* and *Status* from each `mod.json`; add the GameBanana link by hand; `node tools/split-missing.js` after editing a download; `node tools/pending.js` regenerates `PENDING.md`.

## Balance mods (copies)

A mod that only changes the game's civilizations (stats, costs, specials, orders: Community Mod, Caesar Mod, MCI, Secuter, Nucl3arW1nter...) is ported as **one clone of each of the game's civilizations, labelled with the mod** (decided in community-mods#15, option 1-C). The game's eight are never edited, the mod is never an exclusive ruleset, and the lobby is not flooded because the host allows **only the mod's set** in a room (imperivm-resurrected#38). Models: `tools/mediterranevm-alpha.js` (the closest, with art and voices) and `tools/nuclear-fazioni-equilibrate.js` (the smallest: classes and orders only, from a 1.40 mod through `port-140.js`). The recipe:

1. **Reserve an id token** with the maintainer (a letter: Nucl3arW1nter is `n`, Mediterranevm `m`) and give every civilization an id that starts with it (`ngaul`, `nrome`, `nimperial`, `ncarthage`, `nbritain`, `niberia`, `negypt`, `ngermany`). The SDK derives the prefix from the id (`Nga`, `Nro`...), there is no `index` and no `letter`, and **two ports with the same derived prefix cannot be active together**. Add a row per prefix to `sdk/prefixes.md` of the SDK repo (through `PR-NOTES.md`, not by hand) and check [CIVILIZATIONS.md](CIVILIZATIONS.md).
2. **Find what the mod changed**: for a 1.40 mod, `port-140.js` into a temporary folder (the merge with HD keeps HD's fixes); `node tools/mod-class-diff.js <DATA/CLASSES> --hd` lists the changed classes by civilization and the base classes (`Hero`, `Melee`...). Compare the commands and the INI/XML tables file by file against HD: a file that is identical to the game's is not a change.
3. **Write a tool** `tools/<id>.js` (idempotent: the same result twice, it deletes `ported/<id>` and rebuilds it). It puts the mod's classes in `MERGED/classes`, its command files in `MERGED/commands` and the changes of the **base classes** in `MERGED/base-changes.json` (they go **inside each clone**, never in `Hero` or `Melee`), and calls `tools/lib/clone-civs.js` with the eight civilizations: `LABEL` is the dropdown's text (`<civ> (<Mod>)`, at most ~22 characters: `Rep. Rome (Nuclear)` is 19), `cloneAllOrders: true` makes the orders the clones share with the base civilization their own copies with the mod's costs, and the clone gets the mod's version of every class and order it changed. Options for the odd cases (`asBase`, `neutral`, `keepImp2`, `branch.hide`) are in the header of `clone-civs.js`. Create `ported/<id>/DATA/SUBAI` before calling it (the library looks there for the port's scripts).
4. **The set**: `mod.json` `name` is the mod's name **with its version** (`Balanced Factions 2.6`): the room names the set after it. Every civilization has `ai: true`; leave `random` alone and avoid `replacesBase`, `variant` and `ownAi`. Hand fixes go in `extras/<id>/` (`mod.json`, `NOTES.md`), which the tool copies at the end.
5. **Scripts the mod edited** are never shipped at the game's path: a copy with a name of its own (`NAME_<tag>.VS`, built as HD's script + the mod's edit with `git merge-file` HD, 1.40, mod; HD often has the edit already) that the clones' classes point to, or a patch that only acts on the mod's own researches, orders or classes (`tools/lib/own-scripts.js`, `own-ai.js`, `greek-ai.js`, `mode-rules.js`). Test the civilization with `Mod_TrueRace(obj)` / `Mod_PlayerCiv`, never `GetPlayerRace` or `.race`; class ids a script writes as text are each clone's own; anything the engine calls by name that returns a value goes as a block inside the game's script that only runs for the mod's civilizations. `CONST.INI` / `AI.INI` / `UNIT_SPECIALS.INI` patches only add keys the game lacks, never change a value the game has. Say in `NOTES.md` whether engine#15 (`Sleep` inside a script started with `AIRun` crashes the game) touches an AI script of the port: never `AIRun` the main economy loops.
6. **What stays out** (it is global: see *Rules packs* below), written in `NOTES.md` under *Left out because it is global*, with the reason: a script that would replace the game's at its path (`UNIT_ON_KILL.VS`), a value of a shared table that the game already has, and an order whose source is a game **base** class (`skill_frenzy` has `src Hero`: the clone would not own it, and a patch would change the game's heroes too).
7. **Check**: `validate-mod.js <abs path of ported/<id>> --game "$G" --data originals/game-data/DATA` (0 errors); `node tools/shared-paths.js <id>` (0 class ids in common with the game and every other port); build twice and compare `md5sum` of every file; `NOTES.md` with what the mod changed, what was ported, what was left out and why, what was tried in game and what was **not**. Then a room with only the set (dropdowns, random, AI), a skirmish with the set alone and with the game's civilizations too, and `Logs\imperivm\imperivm-mod.log` for `compilation error`.
8. **Not in the port**: maps that `require` the mod (rewritten to the clones' classes in community-mods#8: list which maps and which classes in `NOTES.md`); conquests (renamed by `tools/lib/conquests.js` **before** `tagCollisions`, and a civilization's territory takes its `index` as `interface`, which needs imperivm-resurrected#45); `incompatibleWith` (say in `NOTES.md` what overlaps instead). Several balance ports of the same units can be active together: each is its own civilization.

Traps found: `clone-civs.js` only takes the orders whose sources are the civilization's own classes, so a change to an order of a base class stays out (6); the mod's `UNIT_ON_KILL.VS` merge takes the mod's side where HD rewrote the same lines (check `raw/port-140/<id>.md`); a behavior script with the base civilization's race test is copied by `clone-civs.js` without it (`..._<civ>.VS`) or the game restarts it forever; `rm -rf ported/<id>` before a rebuild, or classes of an older build stay.

### Rules packs (what a clone cannot carry)

Two cases need a **world rules pack** instead of (or next to) the clones (AGENTS.md, *World rules packs*): a mod whose content is all global (a neutral object, the capacity of a base class, a script of the game: `oggetti-in-tutte-le-strutture`, `oggetti-in-tutte-le-strutture-e-forti-bilanciati`), and the part of a balance mod that is global (`UNIT_ON_KILL.VS`, a value of `UNIT_SPECIALS.INI`: it goes in *Left out because it is global* of the civilizations pack's `NOTES.md`, and a `<id>-rules` pack is built later from that list). A rules pack:

- has **no clones, no `civs/` folder and no set**; a mod that is only global keeps its **original id**, the `-rules` suffix is for the global part of a mod that also has civilizations. Category *Gameplay & Balance*.
- is **patches only** (`patches/`): `<add>` / `<set select="/class/properties[@attr]" .../>` on the game's classes, `<add select="/items">` for items, `@before` / `@after` / `@replace` directives for scripts. Never a whole file at the game's path. Items, item scripts and orders have **ids of their own** with the pack's token (`oGold1000`, `Q_DEPOSIT_GOLD.VS`), so two packs never share a name.
- says in the `mod.json` description, **in the three languages**, that it changes the game's own classes and values **for everyone while it is on**, and which packs it cannot be used with. `NOTES.md` lists which packs edit the same classes or lines; there is no `incompatibleWith` (the manager already treats packs that patch the same paths as "use only one").
- **A script of the game is patched in place, not copied.** A `<behavior>` of a child class does **not** replace the one it inherits: `CVXScriptClass::ResolveMethods` (`005a5fd0`) appends the parent's behaviors after the child's (at most 8) and `CVXScriptObj::Start` (`005aec40`) starts them all, so a copy named in the child class would run next to the game's script. `tools/oggetti-in-tutte-le-strutture.js` generates the directives from `diff -U0` of HD's script against the mod's (anchored on lines no earlier line repeats, emitted from the bottom up) and applies them with a copy of `PatchScriptText` to prove the result is the mod's script.
- Build it like the others (`tools/<id>.js`, same result twice, `validate-mod.js`, `shared-paths.js`, `NOTES.md` with tried / not tried). The validator does not compile the code of a script patch: the first test is `imperivm-mod.log`.

## Maps and adventures (`wrap-map.js`)

Resurrected runs on the HD game, so a map made for 1.40, 1.56, a mod or an older Imperivm breaks if it places a unit or object HD doesn't have. `wrap-map.js` checks every class the map places (and the ones its scripts create) against the HD data, the big mods in `originals/mods/` and the class mods in `ported/`:

**Packs and other languages.** A pack of maps with no post (`originals/forum/<pack>/files/*.zip`, e.g. the Greek Mod's `Greek_MapsAdventures.zip`) is audited first: `node tools/audit-pack.js <extracted pack> extras/<pack>/AUDIT.md --game "<game>"` says which maps we already have (so they are skipped), which are another edition and which are new. A new one is wrapped with `node tools/wrap-map.js "pack:<pack>/Adventures/<file>.BFHP" --author "Name; Other name" [--lang Italian]`: only that map, its preview and the videos it plays are unpacked, `--author` is required (the credits, separated by `;`) and `--lang` is the language of its texts (the card gets an Italian description too when it is Italian). The same adventure in another language goes **into the mod we already have** with `--add pack:<pack>/<map>`: both maps are listed in the game as `<name> (Español)` and `<name> (Italiano)`, and a video the entry already has is never replaced. Rows made this way have no post to match, so they name their `ported/` folder in parentheses (`… (guerra-dei-mercenari)`) and `sync-table.js` finds them by that.

- a mod that has every class the map lacks goes in `requires` (with several, the first of Community Mod, Greek Mod, Caesar Mod); one that hides an HD class the map uses goes in `incompatibleWith`. `MODS.md` shows both in *Type*;
- a map that needs a mod not ported yet (⏳, ids `forum-t<topic>`) or classes nobody has (❌) is reported and left out of `ported/`;
- classes are also known by their `altid`, the old name HD still accepts (`RWallsN` is `Rwalls2` in Imperivm II maps); parts of the `.bfhp` are compressed and mangle some names, so an unknown name only counts if placed at least twice;
- a map HD already ships (same bytes) is skipped; a file name another ported mod has is renamed `<name> (<id>).bfhp`; videos go to `movies/`; players are the lobby slots (playerdata ids 0–7) a human can take;
- files in `extras/<id>/` are copied into the mod, and their classes count as known.

Nothing in the map changes, so the original author is the only author (no porter credit). Saga entries are credited to Haemimont Games and FX Interactive. `--players` overrides the players tag; `--file <text>` keeps only the downloads whose name has it. A GameBanana mod with no `mod.json` gets the id `gamebanana-<id>` in the game.
